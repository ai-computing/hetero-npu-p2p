# KONI 이종 PD 최적화 및 llm-d HTTP 시험 (2026-10-15)

## 결론

RNGD 1장 prefill + ATOM 2장 B4 decode 구성에서, llm-d HTTP 경유 16개 동시 요청의 처리량 중앙값은 출력 32토큰 **87.93 tok/s**, 128토큰 **100.67 tok/s**였다. 배치가 채워지는 부하에서 기존 이종 PD의 처리량 개선이 HTTP 요청 경로에서도 유지됨을 확인했다. 모든 부하나 카드당 효율에서 우세하다는 뜻은 아니다.

## 구현한 개선

- NPU callback을 기다리는 동안 잡고 있던 broker 전역 잠금을 제거했다. 상태 변경만 잠금으로 보호하여 여러 요청이 동시에 decode 대기열에 들어갈 수 있게 했다.
- 두 ATOM B4 replica의 admission/decode를 소유 스레드에서 관리한다. 한쪽 decode 동안 다른 쪽 KV 준비·DMA가 가능하다.
- B4 커널이 모든 slot을 접근하므로 실행 중인 replica에는 KV를 덮어쓰지 않는다. CQE 완료 전 decode, 중복 요청, 오래된 완료 통지, 실패한 버퍼 재사용을 거부한다.
- 입력 길이와 출력 길이가 다른 요청을 지원하고, 빈 slot은 dummy lane으로 처리한다. 부분 배치는 기본 10ms 대기 후 실행하지만 prefill/자원 대기 시간은 별도다.

## 시험조건과 결과

KONI-Llama3.1-8B-Instruct-20241024, 고정 revision `0172bf7e73977ae213613529f3d2d5400a33f678`. RNGD1, ATOM2/3, context512, greedy non-streaming, 입력140/167/227/271토큰. 출력 길이를 고정하기 위해 EOS 종료 없이 지정 길이까지 생성한다. 공식 llm-d routing sidecar의 shared-storage 제어 프로토콜을 사용하며 KV 데이터는 HTTP 대신 DMA로 전달한다. NIXL/Mooncake 구현이나 Kubernetes 배포 검증은 아니다.

각 시나리오 3회 반복. 총177요청(워밍업24, 측정153), 45개 decoder batch. 단위는 HTTP 요청 시작부터 모든 응답 완료까지의 총 출력 토큰/초다.

| 조건 | 요청 수/회 | 중앙값 tok/s | 3회 범위 |
|---|---:|---:|---:|
| 동시 요청, 출력32 |16|87.93|86.62–88.72|
| 동시 요청, 출력128 |16|100.67|100.59–101.40|
| 출력32/64/96/128 혼합 |8|62.14|60.27–63.08|
| 50ms 간격 도착, 출력32 |8|84.13|70.95–85.11|
| 부분 배치, 출력32 |3|36.77|36.54–36.88|

177개 요청 모두 같은 B4 모델의 host KV admission 기준 전체 logits와 정확히 일치했다. slot 이동과 부분 배치도 포함한다. 이는 전송·실행 경로의 일치 검증이며 원모델 정확도 평가와 다르다. 사용한 유효 배치 크기는 B4 42회, B3 3회였다. DMA는 요청당 중앙값 **3.158ms**, 모든 요청에서64/64 CQE 완료를 확인했다. unit test31개 통과, 서버와 양쪽 worker 정상 종료 및 NPU context 반환을 확인했다.

## 단독 실행과 비교할 때의 한계

이전 동일 입력/출력의 라이브러리 파이프라인 시험은 PD **87.83 / 96.88 tok/s**, RNGD 단독 **61.56 / 66.28**, ATOM 단독 **40.15 / 52.26**이었다(각각 출력32/128). 해당 비교에서 PD 처리량은 RNGD 대비 약1.43/1.46배, ATOM 대비 약2.19/1.85배다. PD는3장, 단독은1장이므로 동일 카드 수 비교가 아니다. 이번 HTTP 시험은 별도 측정 경계이므로 이전 단독 측정과 섞어 새로운 공정 비교 배율로 제시하지 않는다.

이번 HTTP 시험에서는 전력을 측정하지 않았다. 이전 실측에서는 ATOM 단독의 tokens/J가 PD보다 높았으므로, 처리량 개선을 전력효율 우위나 MFU 목표 달성으로 해석하면 안 된다.

## 아직 남은 병목

DMA 자체보다 decode 약70ms/step와 배치 충전율의 영향이 크다. 출력 길이 혼합 시 짧은 요청도 해당 B4 batch의 가장 긴 요청이 끝나야 응답을 받는다. 다음 개선 후보는 출력 길이별 대기열, 완료 요청의 조기 응답, 낮은 부하에서 단독 경로 선택이다. 동작 중인 B4 replica의 빈 slot에 새 KV를 넣는 continuous batching은 현재 안전 조건상 지원하지 않는다.

prefill만 성공하고 decode가 오지 않는 요청의 TTL 정리는 현재 다음 broker 요청 시 수행된다. 별도 주기 정리기가 없는 실험용 서버이므로, 일반 서비스 배포 전에 취소·누락 요청과 자동 정리 동작을 보강해야 한다. 공개 SDK 전체 버전·모델·노드 토폴로지에 대한 범용 동작을 주장하지 않는다.
